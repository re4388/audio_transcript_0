# Jev + Claude，男女搭配，幹活不累

## 一句話總結
Jev 是不生文字、只做選擇題的「System 1」直覺模型，反應只要零點幾秒、輸出還不收費。把它接進 Claude Code，就能在三個位置發揮作用：幫 Claude 挑模型與挑 skill、海量資料的分類打分、以及程式寫完後的自動化驗證。

## 核心論點
1. **Jev 只做一件事：做選擇題**：你給它資料、問題跟幾個選項，它只回你每個選項的機率。因為不生文字、不搞長篇推理，所以反應快到只要零點幾秒，而且便宜到輸出完全不收費。
2. **心理模型：System 1 對 System 2**：TypeSafe 官方把 Jev 定位成 System 1 模型，靠的是直覺反射；像 Fable、Astra 這些大模型則是 System 2，負責深度推理。要做的是把這個直覺反射神經無縫接進 Claude 的大腦裡。
3. **接入方法簡單到有點不像話**：去 TypeSafe 官網註冊拿一組 API key 就好，現在不用排隊、全面開放，註冊還送 5 美元額度；不想走官方也可以透過 OpenRouter。拿到 key 之後，把 key 連同 Jev 官方文件網址貼給 Claude，補一句「這一步不准用大模型，只准用 Jev」，Claude 就會自己去讀文件，決定這題該用是非題、單選題還是打分機制，連選項怎麼設計都幫你想好。更建議把這個設定包成一個 skill 或開關指令：打開時所有適合做判斷的任務優先丟給 Jev，關掉時回到原本運作方式，隨時可以做對照。
4. **位置一：幫 Claude 挑模型**：平常很多人開著 Opus 或 Fable 一路用到底，但一天下來很多任務根本用不到這麼強的模型（找檔案、轉格式、看函式參數，用 Haiku 就綽綽有餘）。把這個判斷交給 Jev 後，你每送出一句話，Jev 會在零點幾秒內掃一眼，判斷這題需要哪個等級的模型再派任務。社群對照測試拿 12 個任務比較：一組全部用 Fable 5.1 硬幹，一組讓 Jev 先做路由分配，結果 9 題根本不需要頂級模型，整體花費省了整整 70%。但要提醒，降級模型的輸出品質夠不夠用取決於你的工作性質與容錯率，一定要自己實測，不要看到省 70% 就無腦全開。
5. **位置一之二：幫 Claude 挑 skill**：skill 越裝越多，每個 skill 的名稱和描述都會被默默塞進 context，每講一句話就重複送出；裝了一百多個 skill，等於每次都要先燒掉上萬個 token，Claude 還得花時間在龐大列表裡慢慢挑。把挑選交給 Jev，你的 prompt 就是題目、skill 清單就是選項。社群有人在裝了 145 個 skill 的工作區實測 14 次，Jev 總共花不到 5 秒就把正確的 skill 挑出來，交給 Opus 5 自己挑則要將近 30 秒。TypeSafe 官方 Cookbook 也有類似測試：面對 182 個 skill，大模型 agent 自己挑的挑錯比例高達 17%，先讓 Jev 做推薦篩選後，出錯率降到只剩 7.3%。
6. **位置二：海量資料的分類與打分**：核心概念是「Jev 負責先粗篩，Claude 只處理篩出來的精華」。社群用同一套邏輯連續跑了五個真實場景，每次都只丟一句指令給 Claude，Claude 自動調用 Jev 批次完成判斷，最後輸出成表格或儀表板：1400 則 YouTube 留言分五類（Opus 5 跑 34 分鐘、燒 23 美元還是有漏，Jev 只花幾十秒、幾美分）、250 位潛在客戶意向打分（4 秒、1 美分）、203 位新會員流失風險評分（25 秒、1 美分）、1300 則社群貼文分六大類並自動派發（106 秒、4 美分）、227 通客服電話逐字稿歸類（13 秒、7 美分）。在這種封閉式分類場景下，Jev 的準確度不輸 Opus，甚至比 Sonnet 還要穩定。
7. **判斷準則與創作者玩法**：只要你的任務數量非常大，而且每一筆資料都在問同一個問題，那就是 Jev 的主場——這張發票是不是可疑？這封 Email 是不是垃圾信？這則留言有沒有踩到版規？這張退款申請符不符合資格？創作者還可以把一小時訪談按語意切成幾百個候選片段，一口氣丟給 Jev 評分，再拉出前 10 高分片段後製；作者的做法是自己依然會挑，同時用 Jev 跑一次打分交叉比對，把 AI 當第二雙眼睛，撿回疲勞時漏掉的金句。
8. **位置三：程式寫完後的自動化驗證**：Agentic Coding 的品質關鍵在於有沒有一個強大的 feedback loop，但審查與多輪測試正是整個流程裡最燒 token、最花時間的環節，Jev 讓這個驗證迴圈變得極度便宜又極度快速。四種玩法：用語意寫規則的 Linter（規則可以用大白話寫，每個 PR 送出時全自動掃描、成本幾乎等於零）；對整個 codebase 地毯式掃描（前 150 條註解只花 9.3 秒、約 1 美分，整個專案掃完 57 美分，再用便宜的 Haiku 批量重寫，連 code smell 一起掃掉 2800 萬個 token 也只要 1.19 美元）；百問清單的 code review（一次拋出 100 個檢驗問題，只把 Jev 判定高風險的少數幾項送給 Claude 深度修復，能把耗費高階心智的審查內容砍掉將近 10 倍）；大規模對抗測試（併發幾十個無頭瀏覽器，用 Browser-use 團隊開發的 Jev 版瀏覽器 Agent，完成一次蘇黎世到倫敦的機票預訂全流程只花 7 秒、成本 0.4 美分）。
9. **企業級落地與共同架構閉環**：知名監控平台 Sentry 的資安工程師把 Jev 整合進漏洞檢測 pipeline，原本就用小型開源模型降低成本，改用 Jev 之後判斷準確率提升、響應延遲大幅降低，整個 pipeline 運算成本甚至比原先再便宜整整 5 倍以上。背後是同一套架構閉環：Jev 在第一線做極速條件判斷，Claude 在後端監控結果，發現偏差就回頭優化 prompt 規則、調整門檻，調完再放手讓 Jev 繼續跑，直到精準度達標。這本質上就是 System 2 在訓練 System 1，就像學開車，一開始要大腦全神貫注，練久了就轉化成不假思索的肌肉記憶。
10. **貫穿的共同邏輯**：這三個位置原本都是 Claude Code 在做「判斷」的環節，而不是做「生成產出」的環節。只要在你的 Agent 工作流裡，哪一步的本質是在做選擇與判斷，那一步就是留給 Jev 的黃金位置。產業訊號也很明確：OpenAI 在 9 月 29 日 DevDay 發佈了 Decisions API，底層邏輯如出一轍——就算未來不選 Jev，把決策拆成選擇題交由特化模型極速處理，各家巨頭接下來都會跟進。

## 關鍵洞察
- 挑模型與挑 skill 是最低門檻的起手式，因為完全不侵入現有操作習慣，效益卻最直接。
- 省錢與省時間之外，隱藏效益是 context 不再被工具清單塞滿，Claude 不必在龐大列表裡慢慢挑，速度也跟著提升。
- 把大模型昂貴的 token 花在真正有價值的高槓桿環節，粗篩交給便宜的直覺模型，是這整套玩法的經濟學。
- 降級模型的品質夠不夠用因人和容錯率而異，一定要拿自己最常用的任務跑開／關對照。
- Jev 加 Claude 是「System 2 訓練 System 1」的閉環，不只是單向使用工具。
- 最高價值的應用落在開發者的驗證迴圈上，因為 review 和測試本來就是研發中最耗損資源的黑洞。
