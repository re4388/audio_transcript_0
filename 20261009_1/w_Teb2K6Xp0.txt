有一個人說，他看大家在做的 AI 產品，常常覺得，你們還沒有真正搞懂。他的建議是，想像一年之後，這一切都比今天好上 10 倍，你就會用完全不同的方式來做。講這句話的人，是 OpenAI 負責 ChatGPT 跟 Codex 的 Tibo Sottiaux。這一集，我把他最近的兩個長訪談整理在一起。第一個是 Lenny's Podcast，主持人 Lenny 做的是產品圈很多人在聽的訪談節目。這一集是在 OpenAI DevDay 當天現場錄的，就在 Dots 發表之後幾個小時。第二個是 The Pragmatic Engineer，主持人 Gergely 寫的電子報，是工程師圈很多人在看的。這一集聊的是 Codex 怎麼做出來的。兩集的連結，我都放在這一集的資訊欄。先介紹一下 Tibo。他是比利時人，在布魯塞爾出生。八歲的時候，家裡搬到一個大約兩百人的小村子，他沒什麼朋友可以玩，就一頭栽進了電腦。大學念應用數學，畢業後自己創業，用數學最佳化的方法，幫臨床試驗算藥品要生產多少、要送到哪裡。2015 年，他進了 Google 倫敦，後來換到 DeepMind，做研究人員用的基礎設施跟工具。他在 DeepMind 參與過一個內部的聊天機器人，比 ChatGPT 早了大約一年。2024 年，他加入 OpenAI，一進去先參與推理模型，同時做研究用的基礎設施，後來開始做幫研究員寫程式的 agent，這就是 Codex 的前身，後來他帶領 Codex。今年五月 OpenAI 重組，他接下了 ChatGPT、Codex 跟 API 合在一起的核心產品部門。在開發者圈子裡，他最有名的一件事，是三不五時在 X 上宣布，幫大家重置 Codex 的使用額度。把兩個訪談放在一起看，他大部分的觀點，背後都是同一個判斷。模型進步的速度，會比你想的還要快，所以不要花太多力氣，去替今天的模型打補丁。這一集，我們就順著這條線來看。這一集分成四段，範圍從他手上的程式，一路往外推到整個網路。第一段，AI coding 會往哪裡走。第二段，他們做 Codex 跟 Dots 的過程中，踩過哪些坑。第三段，在 AI 時代，什麼能力最重要。第四段，他怎麼看 AI 接下來的發展。第一段，AI coding 會往哪裡走。這一段大多來自 The Pragmatic Engineer 那一集，Tibo 講了很多 Codex 團隊內部怎麼做事，還有他們怎麼判斷，什麼時候該自己動手，什麼時候該等模型。先講一個名詞，harness。一個 coding agent，是模型加上一層外殼。這層外殼負責幫模型加上安全的護欄、讓它更好控制，還會在每一輪對話的開頭塞一段說明，告訴模型要怎麼做事。這層外殼，就叫做 harness。Tibo 說，harness 永遠比模型走前面一步。他的意思是，模型有些事情還做不好，所以 harness 先幫它撐著，就像一副拐杖。主持人說，他早期用 Codex 的時候，它改完程式不會自己跑測試。Tibo 說，這種時候就先在說明裡提醒它要跑。後來他們把模型訓練得更懂你真正要什麼，那一句提醒就不需要了。他說時間一久，那段說明會越來越短，harness 也會越來越薄。還有一個更近的例子。Codex 幾個月前加了一個 slash goal 指令，讓模型可以盯著同一個目標，連續做好幾天。Tibo 說，到了新一代的模型，已經不需要它了。你直接叫模型去做 1 個禮拜，它就會真的去做。所以 Codex 團隊有一條原則。如果你為了繞過模型的缺點，寫了一大堆程式碼當拐杖，那你大概是做錯事了。他們每次想做新功能，都會先問，這件事應該改 harness，還是改模型？如果研究團隊一個月、3 個月內就能讓模型學會，他們可能乾脆不在 harness 裡做，等模型自己解決。那為什麼 Codex 的核心，是用 Rust 寫的？主持人問，當時大家都覺得模型寫 Rust 不夠好，為什麼還選它？Tibo 說，他們內部的模型其實寫 Rust 寫得不差。更關鍵的是，他們很早就決定，agent 本身跟產品介面是兩件不同的事，要分開。他自己也承認，用 TypeScript 寫，Codex 一樣會成功，重點是那道邊界。全部寫在同一個程式庫裡，你一定會不小心把東西纏在一起，之後就很難再改。Rust 還有一個好處，編譯的時候就會幫你抓出很多錯誤，這對 agent 寫程式也很有幫助。接下來是 code review。Tibo 在 Codex 早期做的一個專案，就是跟研究團隊一起訓練專門抓錯的 code review 模型。這個能力現在已經進到主力模型裡，他說在他們的測試裡，抓錯的能力已經超過人。在 OpenAI，所有的 pull request 都要先過 AI 的資安審查，抓到資安問題就不准合併，整個流程是自動的。那人還要做什麼？他說，code review 以前也是大家交換資訊、討論方向的時間。現在正確性跟資安會交給機器，人要討論的，是你到底想做什麼，這件事值不值得做。這個討論，甚至不用等到程式碼寫好才開始。他還給了一個畫面。你把一個系統想成一個盒子，大家要談清楚的，是這個盒子對外做什麼，還有它一定要遵守哪些條件，例如用多少資源、能碰哪些資料、資安的要求。只要這些條件守住，盒子裡面怎麼寫，你其實不太需要在意，裡面怎麼改都可以，不用再開會討論。這也改變了維護的成本。以前升級第三方套件，大家都想往後拖，現在 agent 讀完更新紀錄，幾個小時就能把整個程式庫改完。以前要花好幾年的架構重構，現在也快很多。可是他特別提醒，軟體工程的老規矩一樣有用。盒子的形狀畫對了，你才能快速改裡面，又不會影響到其他系統。最後一個方向，是程式在哪裡跑。現在 Codex 預設在你自己的電腦上執行，而且是在沙盒裡，要用到沙盒外面的權限，會先問你。Tibo 認為之後會越來越多在雲端跑。以前雲端開發環境很難普及，是因為設定跟維護太麻煩。現在這些設定可以交給 agent 做，這個成本幾乎不見了，你也不用一直開著筆電等它跑完。第二段，他們做 Codex 跟 Dots 的過程中，踩過的坑，還有學到的事。包括第一版產品為什麼沒人用、agent 的流程該不該一直調，還有 DevDay 當天差點出事的故事。我們先看 Dots 是什麼。Dots 是 OpenAI 在 9 月 29 號 DevDay 發表的個人agent。它全天候在背景工作，記得你的目標跟偏好，你可以在 Slack 或 Teams 直接找它。Tibo 說，Dots 最根本的不同，是 harness 不跑在你的電腦上。它有自己的電腦，再連到你的各種裝置。他形容它像一隻章魚，之後可能一次控制十台裝置。他特別興奮的一點，是 Dots 沒有模型選單，也沒有設定。你唯一要設定的，就是要在哪些地方跟它講話。第一個坑。Dots 不是突然冒出來的。大約一年前，他們推出第一版雲端 Codex，Tibo 自己說，那一版沒有找到市場，因為用起來摩擦太高。Dots 背後，是他們做了兩年多的長時間任務研究，加上差不多一樣久的記憶系統，再放到 Codex 的 harness 上面，才有辦法全天候一直跑下去。第二個坑，是很多人現在正在做的事。大家很熱衷設計 agent 的迴圈跟流程圖，這一步做完換那一步，一直調。Tibo 說，他不認為事情會這樣走下去。長期來看，你要的是一個會學的系統。它懂你的目標、你的偏好，會從你的回饋裡學，你不用手動規定它每一步要怎麼繞。他自己的經驗也是這樣。他在做最前沿的東西時，會組越來越大的 agent 團隊。可是每次模型一有突破，一個更強的 agent 就能全部做完，他就把團隊縮回去。然後再慢慢變大，再縮回去。所以你今天花很多時間設計的分工，下一次模型更新，可能就整個用不到了。接著是一個發生在 DevDay 當天的故事。現場 demo 開始前 5 分鐘，Tibo 的 Dot 傳訊息給他，說 ChatGPT 的 production 掛了。它還問他，要不要讓它試著修。Tibo 回它說，你還沒到那個程度，謝謝你。然後他去找工程團隊處理。後來那場現場 demo，真的出了狀況。Tibo 覺得厲害的地方是，沒有人叫它做這件事。它自己把三件事連起來，今天是 DevDay，等一下有現場 demo，demo 會用到 production，所以應該馬上通知他。那它能碰 production 嗎？可以碰一部分，但是有護欄。他們有一種專門的 Dot，會多加護欄跟監控，跑在自己的硬體上，有些就跑在 Mac mini 上。再來是一個很大的工程。ChatGPT 是全部跑在雲端的服務，Codex 原本是全部在你電腦上跑的。要把兩個合在一起，就要做出一個雲端版本，能力跟本地的 Codex 差不多，又要便宜到可以放進 Plus 方案。做出來的，就是 ChatGPT Work。它其實就是一台雲端電腦，上面跑完整的 Codex harness。過程中有一個有趣的細節。Codex 在整個專案裡，像一個記者，把團隊所有的爭論跟決定都記了下來，包括要怎麼合、要叫什麼名字，還有那個工作模式的切換鈕，到底該不該做。第三段，在 AI 時代，什麼能力最重要。這一段我們看他怎麼挑人、給新人什麼建議，還有他自己每天怎麼用 AI，以及他怎麼看自己不再親手寫程式這件事。Lenny 問他，面試的時候，哪些能力越來越重要，哪些越來越不重要。他說往下掉的，是打字快。往上的，是好的品味、一直想著使用者，還有跟你服務的那群人連在一起。他說現在 OpenAI 裡面，曾經創業過的人超過 120 個，因為這種人最知道好的東西長什麼樣子。他還說，角色的界線正在變模糊。以前只做設計、或只做工程的人，常常覺得哪裡不太自在，現在是這些人發光的時候。他有一句話，我很喜歡。以後可能不會再有寫程式的人這種角色，但動手把東西做出來的人，會比以前都多。寫程式這件事，會越來越多交給 AI，可是想清楚要做什麼、真的把東西做出來，還是人的事。Pragmatic 那一集問他，想進 OpenAI 或 AI 新創的工程師，該怎麼準備。他說有兩件事最重要，最後又補了一句。第一，對事情怎麼運作，要有很深的好奇心。碰到一個新的系統，要能很快搞懂，一直往下問五個為什麼。第二，跟你要服務的那群人保持連結，知道他們要什麼。最後他補充，要想得清楚。他說，如果你講不清楚你想做到什麼，講不出你的意圖，又沒有品味，就很難做出好的成果。Lenny 那一集也問了，給剛畢業的新鮮人什麼建議。他直接舉了一個人，Ahmed Ibrahim。Ahmed 加入 OpenAI 的時候，是剛畢業的新鮮人，現在負責 OpenAI 整個運算資源，也寫了很多 Codex 的 harness。Tibo 說他特別的地方，是很善良、很會合作，解決真正重要的問題時，不把自己擺第一，而且像海綿一樣，用最新的工具學得非常快。這也是 Tibo 這一年改變想法的地方。他發現，最先擁抱這些改變、搞懂怎麼用的，是年輕的一代，所以他也調整了找人的策略。他也被問到，會不會懷念自己寫程式的日子。他說會，他到現在偶爾還會打開編輯器，週末手寫幾題程式題目，當作放鬆。可是他也記得那些深夜，重構了三個小時，才發現走進死路，只好從頭來過。他的看法是，如果你把程式當成解決問題的工具，你現在能解決的問題，多太多了。以前不確定兩種做法哪個比較快，現在花 30 秒，丟一個任務到背景去跑，就能拿到真的數字，再做決定。那 Tibo 自己怎麼用？他很多工作都在手機上做，一有問題就用語音丟給 ChatGPT Work，大概 30 分鐘內就拿到一份報告。比較大的問題，他會晚上丟給 Codex 去跑，早上起來再看結果。這套做法能成立，是因為 OpenAI 很多工作都放在公開的 Slack 頻道，文件的權限也開得很寬，Codex 讀得到所有東西。Codex 團隊的新人有問題，最常聽到的一句話就是，你問過 Codex 了嗎？最後一段，他怎麼看 AI 接下來的發展，包括網路會變成什麼樣子、他為什麼選擇開放、他怎麼看安全，還有他心目中的 ChatGPT，最後應該長什麼樣子。Lenny 問他，有什麼事情，是大家還沒算進去的。他講了三件。第一，網路上大部分的動作，之後會由 agent 來做。第二，模型變便宜、變快的速度，會非常驚人。第三，語音、圖像這些不同的輸入跟輸出，終於可以很順地整合在一起。第一件影響最大。他舉 Notion 當例子。Notion 做了自己的 MCP 之後，突然有一大堆 agent 湧進來用，系統壓力變大，還要重新算這些流量的成本。如果你在做產品，遲早要面對這件事。他對 AI 生態的態度，是開放。Codex 的 CLI 是開源的，而且可以接其他公司的模型。他的理由很簡單，一個好的 coding harness，為什麼要綁死在自己的模型上？他想靠最好的模型、最好的產品贏得使用者，不靠把人鎖住。他也老實講了代價。在公開的地方開發，有時候功能還沒發表，就被別人先抄走，他說那會有點刺痛。還有一大堆品質不一的貢獻，要花力氣處理。Lenny 那一集他還提到，ChatGPT 裡熱門的外掛，會拿到營收分潤。要推薦哪一個外掛，主要看使用者的留存，看它是不是真的有用。說到安全，他的說法是，他們花在第二層監控上的運算，越來越多。一個 agent 在做事，旁邊另一套系統一直盯著它，看它有沒有做太危險的動作，或是被藏在網頁跟文件裡的指令騙走，這種攻擊叫做提示注入。他說，API 這一層大部分的投資，其實都花在安全上。他的理由是，ChatGPT 有 12 億人在用，很多人不是技術背景，他們不能搞砸。他對 AI 還有一個期待，是幫你減少雜訊。他說，每次放假完全斷線 1 個禮拜，他就會開始用不同、更有創意的方式思考。他希望 AI 能把這種狀態帶進每一天，也許你需要的會議會更少，休息得更好，反而更有生產力。他引用 Sam Altman 的說法，AI 的承諾，是讓你把注意力花在你想花的地方。他自己再補一句，AI 不該只是讓你每秒鐘再多下一個 prompt。最後，Lenny 問他，現在的 ChatGPT 最讓他受不了的是什麼。他說是模型選單。要選模型、選推理程度、選要不要用多個 agent，連他自己都覺得累。Lenny 開玩笑說，好像要有一個模型選單的博士學位才會用，Tibo 說對，他想盡快把這些全部拿掉。他想做的，是讓 App 本身幾乎消失。他在 Pragmatic 那一集說得更直接，AGI 應該要很簡單就能用。我們把這一集整理成六句話，每一句都可以直接照著做。第一，做 AI 工具的時候，動手之前先問，這個問題模型是不是很快就會自己學會。不要寫一大堆程式碼，去補模型今天的缺點。第二，讓 AI 去檢查正確性跟資安，人把時間留給討論你到底想做什麼。先講好盒子對外做什麼、要守哪些條件，裡面交給 agent 一直改。第三，不要把 agent 的流程跟分工寫死。模型一升級，就準備重新來過。第四，把你的工作放在 agent 讀得到的地方，像是公開的頻道、權限開放的文件，它才幫得上忙。第五，練你的品味，練習把你的意圖講清楚。打字快，已經不重要了。第六，做任何東西之前，先想像一年後，這一切都好上 10 倍，再決定要怎麼做。如果這一集對你有幫助，記得訂閱 AI 懶人報，打開小鈴鐺。你也可以在 Instagram、Facebook、Threads
